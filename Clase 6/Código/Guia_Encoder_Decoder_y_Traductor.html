Encoder-Decoder y traductor Seq2Seq

Guia didactica basada en Clase 6/Código/Encoder_Decoder.ipynb y Clase 6/Código/Traductor.ipynb. Primero se aprende la mecanica con una secuencia numerica simple. Luego se aplica la misma arquitectura para traducir frases de ingles a español.

Notebook 1: numeros Notebook 2: traduccion EN -> ES Keras + TensorFlow LSTM Seq2Seq
Mapa mental
Entrada Numeros o palabras tokenizadas
->
Encoder Resume la secuencia en estados h y c
Contexto Estados finales de la LSTM
->
Decoder Genera la salida token por token

1. Conceptos clave antes de mirar codigo

1

Encoder

Lee toda la secuencia de entrada. En una LSTM, su resumen queda en dos vectores: state_h y state_c. Esos vectores son el "contexto" que se pasa al decoder.

2

Decoder

Produce la secuencia de salida. Durante entrenamiento recibe la salida correcta corrida un paso. Durante inferencia recibe lo que el propio modelo predijo en el paso anterior.

3

Tokens especiales

<sos> marca el inicio de la salida y <eos> marca el final. En el notebook numerico solo se usa <sos> porque la salida siempre tiene longitud 3.

La idea que conecta todo: entrenamos el modelo viendo la respuesta correcta completa, pero al usarlo en produccion lo hacemos generar un token por vez. Por eso se construyen modelos separados para entrenamiento e inferencia.
Teoria: que problema resuelve Seq2Seq. Un modelo Seq2Seq transforma una secuencia en otra secuencia. La entrada y la salida no tienen por que tener la misma longitud: una frase en ingles puede traducirse a una frase mas corta o mas larga en español. El encoder convierte la entrada en un estado latente; el decoder usa ese estado para generar la salida ordenada.
Secuencia fuente x1, x2, x3, ... Lo que se quiere leer.
->
Encoder LSTM Procesa paso a paso. Conserva memoria temporal.
->
Estados h, c Resumen aprendido. Condicion inicial del decoder.
Decoder LSTM Recibe <sos> al inicio.
->
Secuencia destino y1, y2, y3, ... Un token por paso.

2. Notebook: Encoder_Decoder.ipynb

Este notebook usa un problema artificial para que la arquitectura sea transparente: dada una secuencia de tres numeros, el modelo debe devolver los tres numeros siguientes desplazados por 15.

Entrada: [x, x + 5, x + 10] Salida: [x + 15, x + 20, x + 25] Ejemplo: [5, 10, 15] -> [20, 25, 30]

2.3 Preparacion del dataset y teacher forcing

El encoder recibe la entrada tokenizada. El decoder recibe la salida correcta desplazada un paso hacia la derecha. Ese procedimiento se llama teacher forcing.

Para el ejemplo

Entrada real: [5, 10, 15] Salida real: [20, 25, 30] Decoder in: [<sos>, 20, 25] Target: [20, 25, 30]

Intuicion

En el paso 1 el decoder ve <sos> y debe predecir 20. En el paso 2 ve 20 y debe predecir 25. En el paso 3 ve 25 y debe predecir 30.

Teoria: por que teacher forcing acelera el aprendizaje. Si al principio el decoder usara sus propias predicciones, cometeria muchos errores y esos errores se acumularian. Con teacher forcing, durante entrenamiento se le entrega la respuesta correcta del paso anterior. Asi el modelo aprende la relacion local "dado el contexto y el token previo, cual token sigue".

def preparar_dataset(X, Y, label_encoder, vocab_size):
    X1_list, X2_list, target_list = [], [], []

    for x_seq, y_seq in zip(X, Y):
        enc_in  = list(label_encoder.transform(x_seq.ravel()))
        enc_out = list(label_encoder.transform(y_seq.ravel()))

        dec_in = [0] + enc_out[:-1]  # <sos> + salida corrida

        X1_list.append(to_categorical(enc_in,  num_classes=vocab_size))
        X2_list.append(to_categorical(dec_in,  num_classes=vocab_size))
        target_list.append(to_categorical(enc_out, num_classes=vocab_size))

    return np.array(X1_list), np.array(X2_list), np.array(target_list)

2.4 Arquitectura Encoder-Decoder

La funcion construir_modelos arma tres modelos. Esto es normal en Seq2Seq clasico con Keras: un modelo se usa para entrenar con toda la secuencia, y dos modelos mas chicos se usan para inferir paso a paso.

Teoria: el cuello de botella del encoder. En esta arquitectura clasica, toda la informacion de la entrada debe pasar por los estados finales h y c. Ese resumen funciona bien para secuencias cortas, pero puede volverse limitado en frases largas. Esa limitacion motivo luego mecanismos como attention y Transformers.
A

model

Modelo completo de entrenamiento. Recibe [encoder_input, decoder_input] y aprende a producir target.

B

encoder_model

Recibe una secuencia y devuelve los estados h y c.

C

decoder_model

Recibe un token y estados previos. Devuelve la distribucion del proximo token y nuevos estados.

Entrenamiento: todo en paralelo

Encoder input [5, 10, 15] Secuencia completa.
->
Encoder LSTM Devuelve h, c.
->
Decoder LSTM Recibe [<sos>, 20, 25].
Salida
P(20) P(25) P(30) vs 20 25 30

Inferencia: un paso por vez

Encoder input [20, 25, 30]
->
encoder_model Produce estados iniciales.
->
decoder_model Predice 35, luego 40, luego 45. 
encoder_input = Input(shape=(None, n_input))
_, state_h, state_c = LSTM(n_units, return_state=True)(encoder_input)
encoder_states = [state_h, state_c]

decoder_input = Input(shape=(None, n_output))
decoder_lstm = LSTM(n_units, return_sequences=True, return_state=True)
decoder_dense = Dense(n_output, activation='softmax')

dec_out, _, _ = decoder_lstm(decoder_input, initial_state=encoder_states)
dec_out = decoder_dense(dec_out)

model = Model(inputs=[encoder_input, decoder_input], outputs=dec_out)
Por que se usa categorical_crossentropy

Porque cada paso temporal es una clasificacion multiclase: el modelo elige uno de los tokens del vocabulario. La salida de la capa densa es softmax, una distribucion de probabilidad sobre todos los tokens posibles.

2.5 Inferencia numerica

En inferencia ya no conocemos la salida correcta. El decoder arranca con <sos>, predice un token, usa ese token como nueva entrada y repite el proceso.

Teoria: generacion autoregresiva. Autoregresivo significa que la salida actual depende de las salidas anteriores. En entrenamiento se usa la salida correcta anterior; en inferencia se usa la salida que el modelo acaba de producir. Esta diferencia explica por que pueden aparecer errores acumulados.
Inicio

token = <sos>
states = encoder(x)

Paso 1

Decoder predice 35. Ese token vuelve como entrada.

Paso 2

Decoder predice 40. Se actualizan h, c.

Paso 3

Decoder predice 45. Termina porque n_steps=3.

Ejemplo de distribucion softmax

El decoder no devuelve directamente "35"; devuelve probabilidades. Luego argmax selecciona el indice mas probable.

def predecir(x_seq, encoder_model, decoder_model, label_encoder, vocab_size, n_steps=3):
    states = encoder_model.predict(x_seq, verbose=0)
    token = to_categorical(0, num_classes=vocab_size).reshape(1, 1, vocab_size)

    output = []
    for _ in range(n_steps):
        pred, h, c = decoder_model.predict([token] + states, verbose=0)
        output.append(pred[0])
        states = [h, c]
        token = pred

    return output
El notebook prueba con [20, 25, 30] y espera [35, 40, 45]. Como la salida siempre tiene tres pasos, n_steps=3 alcanza y no hace falta token <eos>.

3.2 Tokenizacion y padding

Las palabras se transforman en indices enteros con dos tokenizadores: uno para ingles y otro para español. Luego se aplica padding para que todas las secuencias de un batch tengan la misma longitud.

Teoria: por que se usa padding. Las redes entrenan en batches, y dentro de un batch todos los tensores deben tener la misma forma. Como las frases tienen longitudes distintas, se rellenan con ceros hasta una longitud fija. El cero suele representar "sin palabra" o padding.

3.3 Dataset eficiente y embeddings GloVe

Para no materializar todos los targets en one-hot desde el principio, el notebook usa tf.data.Dataset. El one-hot del target se crea dentro del pipeline.

Teoria: embeddings versus one-hot. Un one-hot de 8000 palabras es un vector enorme y casi todo en cero. Un embedding reemplaza cada indice por un vector denso mas chico, por ejemplo de 50 dimensiones. Palabras semanticamente parecidas tienden a tener vectores mas parecidos, lo que ayuda al encoder a arrancar con informacion linguistica. 
def make_dataset(enc_seqs, dec_in_seqs, dec_out_seqs, batch_size, num_classes):
    def encode_one_hot(enc, dec_in, dec_out):
        y = tf.one_hot(dec_out, depth=num_classes)
        return (enc, dec_in), y

    ds = tf.data.Dataset.from_generator(...)
    ds = ds.map(encode_one_hot, num_parallel_calls=tf.data.AUTOTUNE)
    ds = ds.batch(batch_size).prefetch(tf.data.AUTOTUNE)
    return ds

El encoder usa embeddings preentrenados GloVe de dimension 50 para las palabras de entrada en ingles. La matriz de embeddings tiene una fila por token del vocabulario de entrada.

3.4 Modelo Seq2Seq para traduccion

El encoder toma una secuencia de indices en ingles, la pasa por una capa Embedding con pesos GloVe congelados, aplica dropout y resume la frase con una LSTM.

Teoria: que aprende cada parte. El embedding convierte simbolos discretos en vectores. La LSTM del encoder aprende a combinar esos vectores segun el orden de la frase. La LSTM del decoder aprende a construir una frase española coherente condicionada por los estados del encoder y por lo que ya genero.

Decoder

Indices ES (batch, 22)
Embedding aprendido (batch, 22, 256)

Compilacion

Lectura de formas: el modelo no devuelve una frase como texto. Devuelve, para cada posicion de salida, una distribucion sobre el vocabulario español. Convertir eso a palabras ocurre despues, durante la inferencia.

3.5 Inferencia greedy para traducir

Como en el notebook numerico, se separan encoder y decoder para inferencia. La diferencia es que ahora el decoder se detiene cuando predice <eos> o cuando llega a max_out_len.

Teoria: greedy decoding. En cada paso, el decoder produce probabilidades para todas las palabras del vocabulario. Greedy decoding elige la palabra con probabilidad maxima y la fija como entrada del paso siguiente. Es una decision local: no reconsidera elecciones anteriores.

def translate_sentence(input_seq):
    h, c = encoder_model.predict(input_seq, verbose=0)
    target_seq = np.zeros((1, 1))
    target_seq[0, 0] = word2idx_outputs['<sos>']
    eos = word2idx_outputs['<eos>']

    output_sentence = []
    for _ in range(max_out_len):
        output_tokens, h, c = decoder_model.predict([target_seq, h, c], verbose=0)
        idx = np.argmax(output_tokens[0, 0, :])
        if idx == eos:
            break
        if idx > 0:
            output_sentence.append(idx2word_target[idx])
        target_seq[0, 0] = idx

    return ' '.join(output_sentence)
Greedy decoding siempre elige el token mas probable en cada paso. Es simple y rapido, pero puede perder traducciones mejores que requieren mirar varias alternativas. Una mejora habitual es beam search.

5. Errores frecuentes y como leerlos

Vocabulario incompleto

Si aparecen tokens fuera del vocabulario, el modelo no puede representarlos correctamente. En el notebook numerico se evita incluyendo entrada y salida en all_values.

Confundir decoder input y target

El decoder input empieza con <sos>. El target termina con el token que se quiere predecir. No son la misma secuencia.

Olvidar reutilizar capas

Los modelos de inferencia deben usar las mismas capas entrenadas. Si se crean capas nuevas, se pierden los pesos aprendidos.

Interpretar mal accuracy

En traduccion, la accuracy token a token puede verse aceptable aunque la frase completa no sea buena. Conviene mirar ejemplos traducidos.
